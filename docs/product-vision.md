# SignalFeed 产品愿景与路线图

> 文档状态：生效中  
> 最近更新：2026-08-11

## 1. 产品定位

SignalFeed 是一个面向大模型与 AI 开发领域的高信噪比信息采集工具。它从高价值官方站点和开发者社区持续发现新内容，经过标准化、过滤和去重后，以简报形式推送到飞书。

项目要解决的核心问题是：AI 开发信息分散、更新频繁、重复内容多，开发者需要花费大量时间浏览多个网站和社区，才能找到真正值得阅读的信息。

SignalFeed 的核心目标是：

> 让使用者每天自动获得一批值得阅读的大模型与 AI 开发信息，而不必手动巡检多个来源。

## 2. 产品原则

- **信噪比优先**：来源数量不是成功指标，稳定输出有阅读价值的内容才是。
- **官方来源优先**：同一事件优先保留厂商官网、项目 Release 等原始来源。
- **确定性优先**：早期使用可理解、可配置、可测试的过滤和去重规则。
- **闭环优先**：先确保采集、筛选、去重、推送能够持续运行，再扩充来源。
- **小步演进**：不为尚未验证的需求提前引入复杂基础设施。

## 3. 目标信息范围

重点关注以下内容：

- 模型、API、SDK 和开发者工具发布或更新；
- Agent、AI Coding、MCP、推理框架等工程进展；
- 重要开源项目、模型和开发工具；
- 有实际参考价值的开发者使用经验；
- 与上下文、推理、评测和部署相关的重要变化。

论文流、泛科技资讯和缺少事实信息的营销内容不是当前重点。

## 4. 路线图

### M1：单一官方信源最小闭环

M1 验证从真实官方信源到飞书消息的端到端技术路径：

```text
OpenAI 官方 RSS
        ↓
      采集
        ↓
 NewsItem 标准化
        ↓
    关键词过滤
        ↓
   SQLite 去重
        ↓
 飞书消息 / 安全预览
```

当前工程已经实现上述代码路径、命令行入口和自动化测试。真实飞书发送仍需在提供 Webhook 凭据后完成上线验收。具体设计和状态见 [M1 技术规格](m1-specification.md)。

### V1 第一阶段：扩充稳定信源

M1 完成外部验收后，优先扩充以下四类信源：

1. **模型厂商官网**
   - News、Blog、Developer Blog、API Changelog 和 Release Notes；
   - 首批候选包括 OpenAI、Anthropic、DeepSeek、Kimi、GLM 和 MiniMax；
   - 优先使用 RSS 或 Atom，没有稳定 Feed 时再采用简单 HTTP 页面采集。

2. **GitHub**
   - 指定组织的新仓库和指定仓库的 Release；
   - 与 Agent、Coding、MCP、Inference 等主题相关的高价值项目；
   - 优先使用 GitHub API 和 Atom Feed。

3. **Hugging Face**
   - 新模型、Trending Models、Trending Spaces 和指定厂商账号；
   - 不在本阶段接入论文流。

4. **Hacker News**
   - 新模型、AI Coding、Agent、API、开源模型和推理框架；
   - 重点保留开发者实践和真实使用反馈。

第一阶段在 M1 管道基础上扩展 Collector 边界，并补充跨来源去重、来源优先级、简报调度和基础排序能力。

### V1 后续阶段：补充高成本渠道

第一阶段稳定后，再评估接入：

- X / Twitter；
- 知乎。

这两个渠道属于 V1 的后续目标，但不阻塞第一阶段上线。是否接入 V2EX、Reddit 等社区，应由实际内容缺口决定。

## 5. V1 成功标准

满足以下条件后，V1 第一阶段可视为稳定：

1. 四类核心信源能够持续采集并统一转换为领域模型；
2. 重复内容不会被反复推送，并能优先保留原始来源；
3. 关键词规则能够筛选出与大模型和 AI 开发相关的内容；
4. 飞书能够按计划生成结构清晰的定时简报；
5. 系统连续运行一周，无需日常人工干预；
6. 大多数推送内容对目标使用者具有实际阅读价值。

## 6. 当前非目标

V1 不包括：

- Web 前端、RSS 阅读器或用户账户；
- 个性化推荐、Embedding、向量数据库或 LLM 内容评分；
- 自动摘要和论文推荐；
- Redis、PostgreSQL、Elasticsearch 或 GPU 基础设施；
- 微信公众号、ModelScope、小红书、微博、B 站等扩展渠道。

上述能力只有在现有闭环稳定且出现明确需求时才重新评估。
